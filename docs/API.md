# API guide

Base URL: same origin as the dashboard. JSON requests and responses. Authentication uses a server session; credentials are not returned to JavaScript. GitHub App user OAuth and explicit local demo sign-in are implemented. Live GitHub authentication still requires credential verification.

| Method | Endpoint | Behavior |
|---|---|---|
| GET | `/api/system` | Public application name and explicit demo-mode flag |
| GET | `/api/csrf` | Public CSRF token and header name for this session |
| POST | `/api/logout` | End session; CSRF required; 204 |
| GET | `/api/me` | Current persisted user profile |
| GET | `/api/auth/config` | Public GitHub sign-in availability and App installation URL |
| POST | `/api/auth/demo` | Local demo sign-in; available only with DEMO_MODE=true; CSRF required |
| GET | `/api/installations` | Installations visible through the user's current grants |
| POST | `/api/github/sync` | Refresh repository discovery and user grants with the server-held OAuth token; CSRF required |
| POST | `/api/webhooks/github` | Verify original-body HMAC and delivery identity; atomically record jobs/outbox; the only CSRF-exempt mutation |
| GET | `/api/repositories?page=0&size=20&search=` | Repositories visible through valid grants, paginated and sorted by name |
| GET | `/api/repositories/{id}` | Repository policy, manage permission and installation account |
| PATCH | `/api/repositories/{id}/policy` | Set repository policy; write/admin grant and CSRF required; audited |
| GET | `/api/pull-requests?page=0&size=20&search=&state=&repositoryId=` | Visible PRs, with optional repository and open/closed filters |
| GET | `/api/pull-requests/{id}` | Persisted PR metadata and review-job history |
| POST | `/api/reviews/{id}/cancel` | Cancel an unfinished job; writer/admin grant, CSRF and audit required |
| GET | `/api/reviews/{id}` | Scoped job, normalized files, findings, provider summary and usage |
| GET | `/api/analytics?days=30&repositoryId=` | Scoped database metrics, weekly trends, findings, activity and usage; days 7–365 |
| GET | `/actuator/health` | Public aggregate status; no sensitive details |

Policy body (send all four fields):

```json
{
  "reviewEnabled": true,
  "cloudAiOptIn": false,
  "publishingEnabled": false,
  "autoPublish": false
}
```

Automatic publishing requires publishing to be enabled. All three consent/publishing flags default to false. Revoked, expired or inaccessible resources return 404 without revealing their existence. A read-only user attempting a policy change receives 403. Query pagination is bounded to 100 records per page.

The frontend retrieves `/api/csrf`, retains the token only in memory, and sends the returned header on mutations. It discards its token after login/logout or a 401/403 response. Requests use same-origin cookies. Never place OAuth/App tokens in localStorage.

Application validation errors use `application/problem+json` with safe details. Authentication and CSRF failures may have empty bodies, which the client handles. Server errors do not echo SQL, provider output or request payloads.

OpenAPI is generated by springdoc. `/api/docs` and `/v3/api-docs` require a session. Publishing endpoints are described below.

Analytics counts review runs created within the selected UTC date window; repository counts reflect current access. PRs reviewed counts distinct PRs with completed runs. Findings are occurrences, not deduplicated confirmed defects. Processing time measures the final completed attempt. Provider token measurements and conservative estimates are separate; monetary costs remain estimates based on configured prices.
# Publishing endpoints

- `GET /api/reviews/{id}/publication`: scoped status, escaped feedback preview and `canPublish`; returns no GitHub credentials.
- `POST /api/reviews/{id}/publication`: writer + CSRF; queues a single publication for the current completed commit if publishing is enabled. Repeated requests return the existing publication.
- `POST /api/reviews/{id}/publication/reconcile`: writer + CSRF; checks an unknown/abandoned submission for an existing GitHub review. Never submits feedback.

See [publishing lifecycle and limitations](PUBLISHING.md). The worker requires `QUEUE_ENABLED=true`; demo repositories cannot publish.
